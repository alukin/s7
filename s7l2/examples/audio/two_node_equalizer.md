# Two-node audio equalizer (G2)

[Diagram](two_node_equalizer.s7diagram) · generated by
`tools/generate_g2_audio_example.py` · run and checked by
`tools/run_g2_audio_demo.py` · design and evidence in
[G2 audio chain](../../docs/G2_AUDIO_CHAIN.md)

One deterministic 48 kHz audio programme crosses from one S7 runtime node to
another. The second node equalizes it and records what it received and what it
produced. Every recorded sample is then checked.

| Node | Elements | Role |
| --- | --- | --- |
| A, `source` | `ChirpGenerator`, five `AnalogOscillator`s, `StepGenerator` gates | The programme: a logarithmic sine sweep from 20 Hz to 20 kHz for 10 s (amplitude 0.25), then steady tones at 100, 400, 1600, 6000 and 12000 Hz (0.08 each). |
| B, `equalizer` | `AudioEqualizer`, five gain `Constant`s, two `RecordingSink`s | The bundled 5-band equalizer with gains +6, 0, −9, +3 and −6 dB; `record_in.s7b` holds the stream as received, `record_out.s7b` the equalizer output. |

The stream between the nodes is buffered: packets of up to 4800 samples
(100 ms), a 100 ms batch limit, and a 5 s wait on node B. Node B runs about one
batch behind node A. When A stalls, B waits; no sample is lost or invented.

## Run it

Two nodes on this computer, then the full check (about a minute):

```sh
python3 tools/run_g2_audio_demo.py local --output /tmp/g2-local
```

Node A here and node B on another Linux host over ssh. Host B needs an S7
build (`s7runtime`), this source tree and Python 3. Open node B's control port
(9202) on host B for the run. Use fresh credentials, not the repository's test
keys:

```sh
tools/generate_test_runtime_certs.sh /tmp/g2-certs
python3 tools/run_g2_audio_demo.py two-host --host-b user@host-b \
    --address-a <this host's address> --address-b <host-b address> \
    --remote-src /path/to/s7l2 --remote-runtime /path/to/build/s7runtime/s7runtime \
    --certs /tmp/g2-certs --output /tmp/g2-two-host
```

The output directory holds:
- `report.md` and `report.json`: correctness results, timing, CPU, memory and
  queue occupancy;
- `response.svg`: the equalizer curve measured from the sweep, against the
  analytic response;
- `input.wav` and `output.wav`: 32-bit float copies for listening, with no
  requantization.

The `node`, `deploy` and `check` subcommands perform the same steps
separately, for example on hosts without ssh between them.

## What is checked

| Check | Reference | Tolerance |
| --- | --- | --- |
| Every sample node B received | The programme, computed in Python from the documented source algorithms: tones as A·sin(2πfn/48000), the sweep with the generator's phase recursion | 1e-9 |
| Every sample node B produced | An independent sample-level implementation of the equalizer's documented bands applied to that input | 1e-9 |
| The same graph in one process | `s7runtime` simulation run of the same diagram, without placement | bit-identical |
| Tone gains | Analytic response \|H(e^jω)\| of the equalizer, evaluated in the frequency domain | 0.01 dB |
| Sweep response at 28 third-octave frequencies | The same analytic response; ratio of RMS levels in a short window around each frequency | 0.5 dB |

A lost, repeated or reordered sample fails the first check at its index. A
changed coefficient or value fails the second and third checks.

## In Studio

- Opening the diagram shows both nodes' elements; the `node` property of each
  element is its placement.
- **Run** executes the same graph locally in one process. The Scope shows the
  programme and the equalized signal. The recordings are written into Studio's
  working directory.
- **Deploy** sends it to the two nodes in the Nodes panel.
- Studio does not observe a deployed graph live. Inspect the recordings
  instead: open `record_out.s7b` with a `RecordedSource` into a Scope or the
  Live Spectrum, or listen to `output.wav`.
